# 流动池发现 —— 指标体系设计 v1

范围：PancakeSwap V3 / BSC 全量池子扫描发现。本篇聚焦**指标定义与组合打分**，架构落地（表结构、迁移、worker 调度）留待方案确认后单独展开。

## 0. 前置决策（影响指标口径的边界条件）

- 本方案是全量扫描发现，**推翻了 `0016_replace_pool_catalog_with_metrics.sql` 的决定**（该迁移曾删除全量 `pool_catalog_entries`，理由是"池子改由地址触发链上发现"）。落地时需在新迁移注释里显式说明这次重新引入全量目录的原因，避免后人误判为回退旧设计。
- 候选池需过**硬性准入门槛**才进入打分：最低 TVL、最低 24h volume、最低池龄、token 白名单（至少一侧为 CAKE/WBNB/USDT/USDC/BTCB/ETH 等主流资产）。未达门槛的池子不产生分数，直接不入库，避免噪音池占用存储和算力。
- 第三方数据（GeckoTerminal）**仅作收益/风险信号来源，不作为池子存在性权威**——池子身份仍需 Factory 链上校验后才能从"候选"升级为"正式池"，与现有 `pools`/`poolMetrics` 的权威性原则一致。
- 历史数据从 v1 起就建（`pool_metrics_history`，逐日快照），因为波动率类指标离不开时间序列。

## 1. 指标定义

指标分三类：**收益类**、**资金效率类**、**风险类**。每个指标都要能区分"确认为 0"和"数据不可得"（沿用现有 `AprEstimateView` 的 `available | no_incentive | unavailable` 三态模式），不能把缺数据静默按 0 处理。

### 1.1 收益类

**Fee APR（手续费年化）**

```
FeeAPR = (24h手续费收入 / TVL) × 365
24h手续费收入 = 24h volume × feePips/1e6 × (1 − 平均协议抽成)
```

- 复用 `estimateFeeDailyUsd`（alpha-engine 仓库 `products/alpha-lp/packages/pancake-v3/src/range-estimate.ts:138`）的池子级变体：现有实现按"用户份额"算，池子发现场景不针对具体仓位，取**全池维度**（不除以 `liquidityShare`）。
- 数据源：GeckoTerminal 提供的 24h volume + 池子自身 feePips（链上 `Factory`/`Pool` 合约常量）。

**CAKE 激励 APR**

```
CakeAPR = (cakePerSecond × 86400 × lmLiquidityShare × CAKE_USD价格 / TVL) × 365
```

- 复用 `estimateCakeDaily`（同文件 line 160），数据源为 MasterChef V3 `poolInfo`/`getLatestPeriodInfo` 实时读取。
- **注意衰减**：CAKE emission 会周期性调整（governance 投票），当前值只代表"当下"，不代表未来 365 天不变。展示时必须标注"基于当前 emission rate 外推"，不能包装成确定性收益。

**名义综合 APR**

```
NominalAPR = FeeAPR + CakeAPR
```

这是最直观但**最容易误导**的数字——不调整风险，纯粹是"如果什么都不变，理论年化是多少"。不能单独作为排序依据，只作为打分公式的一个输入项。

### 1.2 资金效率类

**Volume/TVL 比值**

```
VTRatio = 24h volume / TVL
```

比 APR 更早、更可靠的信号：TVL 低估、APR 虚高的池子会在这里露馅（volume 真实但 TVL 记录不准 → VTRatio 异常高；或者反过来 TVL 堆量但没人交易 → VTRatio 异常低，说明手续费产出效率差）。**建议作为候选池初筛的第一道分数**，而不只是复合分里的一项权重。

### 1.3 风险类

> **v1 修正**：最初版本把"TVL/Volume 稳定性"和"价格波动率"混为一谈。真正驱动 IL 大小、以及集中流动性"跳仓"频率的是**价格波动率**（token0/token1 汇率的波动），不是资金流波动——这是两个独立信号，拆开定义。

**价格波动率 σ_price（核心风险因子）**

```
σ_price = stdev(ln(closeₜ / closeₜ₋₁)) × √365   // 年化，daily close，回看窗口建议 30 天
```

- 数据源：GeckoTerminal 该池子的 OHLCV K 线端点（与现有 `pool-market.ts` 同一供应商，无需新增供应商，只是多调一个端点）。
- 回看窗口 < 30 天（新池子）时标记 `unavailable`，不参与打分——不能拿不足样本的方差冒充结果。
- 这是下面 IL 风险、跳仓频率、推荐区间三个指标共用的唯一输入，三者用同一套 GBM（几何布朗运动）近似模型，保证口径一致。

**IL 风险（价格波动率驱动，连续模型，替代原分类代理）**

```
k = exp(σ_price × √(T_ref/365))              // T_ref 取 7 天参考周期
ExpectedIL_ref = 2×√k / (1+k) − 1
```

- 用"1 个标准差价格波动"代入标准 IL 公式 `IL% = 2√(priceRatio)/(1+priceRatio) − 1` 做近似——不是对全概率分布积分的严格期望值，而是一个可解释、可复现的代表值。
- `T_ref = 7 天`是**打分口径**，与用户实际选的区间宽度无关：所有候选池用同一参考周期比较，避免"谁选的区间宽谁分数好看"的失真。用户具体要开多宽的仓，看下面的"推荐区间"。
- 原来的四档币对分类（稳定币/主流/长尾）可以保留作为 `σ_price` 缺数据时的**降级兜底**，而不是主模型。

**资金流波动率（TVL / Volume 稳定性，独立信号，权重降低）**

```
CapitalVolatility = stdev(近14日 TVL 日环比变化率)
```

- 依赖 `pool_metrics_history` 时间序列，样本不足 14 天标记 `unavailable`。
- 和价格波动率是两回事：这个反映的是"大户资金频繁进出、池子本身脆不脆弱"，价格波动率反映的是"LP 头寸本身会不会亏 IL"。两者都保留，但价格波动率是主风险因子，资金流波动率只是辅助信号。

**跳仓频率代理指标（新增，独立展示，不进复合分）**

```
w_typical = ln(P_upper_typical / P_current)   // 该池当前其他 LP 实际集中的区间半宽（log 价格），来自 TickLens 集中度分布
T_exit_days ≈ (w_typical² / σ_price²) × 365   // 对称区间内布朗运动首次出界期望时间
```

- `w_typical` 复用现有 `ReadonlyPancakeV3RangeReader`（alpha-engine 仓库 `products/alpha-lp/packages/pancake-v3/src/range-estimate.ts:167`）的 TickLens 数据：取当前活跃流动性集中度最高的 tick 区间（如覆盖 60% 活跃流动性的最窄区间）作为"这个池子里大家实际在用的典型区间"。
- 输出语义："如果你跟这个池子里大多数 LP 一样选区间宽度，预计约 `T_exit_days` 天价格会跑出区间一次（需要跳仓维护）。"——不参与打分，只是让用户自己判断维护成本，因为区间宽度是用户的选择，不该被算进池子本身的排名。
- 这是近似模型（假设无漂移的几何布朗运动），且 `w_typical` 依赖 TickLens 集中度快照，本身有噪音，展示时需标注"预估值，仅供参考"。

**推荐流动性区间（新增，独立展示，可操作输出）**

对几个典型维护频率（周期性 rebalance 目标），反推推荐区间宽度：

```
w_recommended(T_target) = σ_price × √(T_target/365)
P_upper = P_current × exp(+w_recommended)
P_lower = P_current × exp(−w_recommended)
tickUpper/tickLower = round(log_1.0001(P_upper/lower) / tickSpacing) × tickSpacing
```

建议默认给 3 档参考（而非单一数字，让用户按自己愿意维护的频率选）：

| 维护画像 | 目标跳仓间隔 T_target | 适用场景 |
|---|---|---|
| 主动型 | 3 天 | 愿意频繁盯盘/跳仓换取更高手续费捕获效率 |
| 平衡型 | 7 天 | 默认推荐，与 IL 打分的 `T_ref` 口径一致 |
| 被动型 | 30 天 | 不想频繁操作，接受更低的手续费捕获效率换稳定 |

- 三档用同一个 `σ_price` 和同一套公式推导，彼此口径一致，用户可以直接对比"更宽的区间要牺牲多少捕获效率换维护频率下降"。
- 这个输出面向"用户已经选中某个候选池、准备开仓"的场景，是发现功能之外顺带产出的可操作建议，不影响候选池排序本身。

**池龄惩罚**

```
AgePenalty = 池龄 < 30天 ? 0.05 : 0
```

新池子数据不稳定、也是钓鱼盘高发期，用固定惩罚项压低排名而非直接剔除（门槛已经拦掉 < 7 天的池子，这里对 7–30 天的池子做进一步降权）。

**TVL 深度分档**

```
DepthTier: TVL < $100k → 高风险；$100k–$1M → 中；> $1M → 低
```

浅池子看起来 APR 高，但进不去多少资金、退出滑点大，需要单独标注深度分档供用户判断"这个 APR 我能吃到多少"。

**大户集中度** —— v1 暂缺数据源（需要额外查 LP 持仓分布，当前链上读取层未覆盖），先留空字段 `whaleConcentration: unavailable`，v2 补齐后再纳入公式。

## 2. 指标组合（复合评分）

### 2.1 归一化

候选池打分前，各指标先在**当前候选集内做 min-max 归一化**到 [0,1]（而非固定绝对阈值），因为"什么算高 APR"会随市场整体行情漂移，相对排名比绝对值更稳定。

### 2.2 复合分公式（v1）

```
CompositeScore =
    normalize(NominalAPR)          × 0.30
  + normalize(VTRatio)              × 0.25
  − normalize(ExpectedIL_ref)       × 0.25
  − normalize(CapitalVolatility)    × 0.10
  − AgePenalty                      × 0.10
```

权重设计意图（相比更早草稿的调整：IL 从静态分类升级为 `σ_price` 驱动的连续值后，可信度更高，因此权重从 0.20 提到 0.25；收益、资金效率各让出一点）：
- **收益（0.30）**：仍是核心考量，但不给最高权重，避免"唯 APR 论"。
- **资金效率（0.25）**：VTRatio 是过滤虚高 APR 的关键制衡项。
- **IL 风险（0.25，`ExpectedIL_ref` 已归一化后减）**：现在是价格波动率驱动的连续值，比原来的四档分类更可信，权重相应提高，和收益/资金效率并列成为三大主因子。
- **资金流波动率（0.10）**：辅助信号，反映池子资金面稳不稳定，权重刻意压低，避免和 IL 风险（同源于波动但语义不同）重复计分。
- **池龄惩罚（0.10）**：略微提高（原 0.05），因为空出的部分风险权重需要有归属，且新池确实是骗局/异常数据高发期。
- **跳仓频率、推荐区间不进复合分**——它们依赖用户尚未做出的区间选择，属于"选中候选池之后"的决策辅助信息，不该反过来影响候选池排序。

### 2.3 数据不可得时的处理

任一分项标记为 `unavailable`（如波动率样本不足）时，**不能当 0 处理**（会错误地拉高或拉低分数），处理方式：
- 该分项权重按比例分摊给其余可用分项重新归一（而不是简单跳过导致总权重<1）
- 复合分旁必须附带 `scoreConfidence`（参与打分的分项数 / 总分项数），前端展示时对低置信度的分数做视觉区分（如置灰或加"数据不全"标注），避免用户误以为是完整评估。

### 2.4 排序与分档展示

不建议只给一个数字排序，按 `CompositeScore` 分档展示更利于用户决策：

| 档位 | 分数区间（归一化后） | 建议展示语义 |
|---|---|---|
| S | ≥ 0.75 | 高收益且风险可控 |
| A | 0.55–0.75 | 收益尚可，需关注具体风险项 |
| B | 0.35–0.55 | 收益一般或风险偏高 |
| C | < 0.35 | 不建议，仅供参考 |

## 3. 退出信号指标（已持仓池子的持续监控）

发现框架的反向应用：同一套指标，从"给候选池排名"换成"给已持仓的池子做持续监控"。现有仓位管理只有**价格位置信号**（`executionIntents` 的 `NEAR_BOUNDARY`/`OUT_OF_RANGE`/`MANUAL` trigger），缺**经济性退化信号**——一个仓位可能一直在区间内、从没触发过这几个 trigger，但池子本身已经不值得继续持有了，这里补上。

### 3.1 与发现框架的关系

- 复用同一套指标计算（Fee APR / CAKE APR / VTRatio / σ_price / ExpectedIL / CapitalVolatility / CompositeScore），计算对象从"候选池"换成"当前持仓所在的池子"。
- 关键区别：发现框架看的是**候选集内的相对排名**（绝对值本身没意义），退出信号看的是**相对开仓时/相对近期均值的退化趋势**——同样是"分低"，一个新池子分低说明本来就不该进，一个持仓池分低说明"变差了"，语义不同，不能直接套用发现框架的 S/A/B/C 分档。
- 建议接入同一个 worker 定时任务：候选池打分之外，也给所有 `positions.status=active` 涉及的池子跑一遍同样的打分逻辑。

### 3.2 具体信号定义

**风险调整净值转负**

```
NetEdge = 近期实际(FeeIncome + CakeIncome)速率 − ExpectedIL_ref（用当前 σ_price 重新计算，而非开仓时的旧值）
```

`NetEdge < 0` 触发——不是"收益变少了"，而是"继续持有的风险调整预期已经是净亏"。σ_price 必须用最新值重算，因为波动率上升本身就是退出理由之一，用开仓时的旧波动率会漏掉这个信号。

**CAKE 激励撤出**

```
cakePerSecond → 0 或 lmLiquidity 大幅下降（MasterChef 治理把 emission 转去别的池子）
```

即 CakeAPR 从 `available` 变成 `no_incentive`（复用现有三态模式）——这个变化本身就是强退出信号，不需要额外阈值判断。

**交易量枯竭**

```
VTRatio_MA(7日) 相比开仓时下降超过阈值（如 −50%）
```

用 7 日移动平均而非单日值，避免被短期噪音（如周末交易量正常回落）误触发。

**相对排名坍塌（机会成本信号）**

```
该池子当前 CompositeScore 在全量候选池中的百分位 < 阈值（如后 50%）
```

这条不是说池子本身"坏了"，而是"同样的资金放去排名更高的候选池，风险调整后收益预期更好"——纯机会成本层面的退出理由，权重上应该比前几条更弱（避免用户被频繁建议挪仓，反而在 gas 和滑点上吃亏）。

**累计已实现 IL 超过累计手续费收入（最直接的"倒亏"信号）**

```
RealizedIL(USD) = f(开仓时价格, 当前价格)   // 标准 IL 公式，用实际发生的价格比，不依赖波动率估算
CumulativeFeeIncome(USD) = 累计 feesOwed + 已领取手续费 + 已领取CAKE
触发条件：RealizedIL(USD) > CumulativeFeeIncome(USD)
```

这条不依赖 GBM 假设或波动率模型，只用实际发生的价格变化和实际到手的收入对比，是最少假设、最可信的信号，建议在几条里权重最高。

**需要补数据**：`positions` 表目前没有存开仓时的价格快照，是这条信号唯一的新增数据依赖——需要新增字段（如开仓时的 tick 或 `openPrice0Per1`），或从 mint 时的 `executionRuns`/`executionSteps` 历史回溯计算。其余信号都只需要复用发现框架已有的计算逻辑，不需要新数据。

### 3.3 触发方式：只做提醒，不接自动执行

v1 建议**只做展示提醒**，不直接接入 `executionIntents` 触发自动减仓/关仓：

- 这几条信号（尤其 CompositeScore 排名、σ_price 突变）都是**模型估算**，不是像"价格已经出界"那样的确定性事实。误报的代价是让用户做了不必要的操作，白付一次 gas + 滑点。
- 建议先作为独立展示状态叠加在 position 详情上（如 `exitSignal: none | watch | recommend_exit`，附带触发的具体信号列表），由用户自己看信号决策，不自动执行。
- "累计已实现 IL 超过累计手续费"这条例外——它不依赖模型假设，是可以考虑未来升级为自动触发的候选，但仍需要先以提醒形式跑一段时间、观察触发频率是否合理，再谈接入 `executionIntents`（可能新增 `POOL_ECONOMICS_DEGRADED` trigger 类型）。这是比本版范围更大的信任跳跃，应该单独拉一次方案讨论。

## 4. RWA / 锚定真实资产池的额外指标

当池子里的 token 是挂钩真实资产的代币（如链上 QQQ/SPY 类跟踪凭证）时，风险结构和纯加密货币对根本不同，需要在前面的框架之外叠加一组新指标。这类资产不适合直接套用"稳定币/主流/长尾"分类，也不能直接套用纯 GBM 连续波动率模型。

### 4.1 核心区别：不是"有没有交易"，是"有没有实时锚点"

这类代币链上/交易所是全天候有成交的，**不能**假设非美股交易时段就没有价格发现（早期草稿的这个假设是错的）。真正的风险点在于：**支撑价格贴住真实净值的最强纠偏机制（跟真实市场/期货实时套利）在某些窗口会暂时缺席**，而不是完全没人交易。对 QQQ/SPY 这类有深度期货市场（接近 24/5 交易）的标的，真正的"锚定真空窗口"其实很窄——主要是**周五收盘到周日期货重新开盘**之间，以及少数交易所公共假期，不是每天美股现货收盘后都算。

### 4.2 锚定跟踪误差（Tracking Error）—— 核心新增指标

```
TrackingError = |链上价格 − 链下参考净值/期货公允价| / 参考价
```

- 需要新的外部数据依赖：一个能反映真实标的（NAV 或对应期货公允价）的参考价格源，当前 GeckoTerminal/CoinGecko 都是加密原生数据，没有这类数据，需要单独接入（如相关预言机 feed 或发行方披露的 NAV/期货报价）。
- 长期 TrackingError 小且稳定，说明套利/赎回机制运作正常；持续走阔或长期偏离，说明锚定机制已经松动，是比 σ_price 更直接的风险信号。

### 4.3 波动率拆分为两部分（替代纯 GBM，采用跳跃扩散思路）

不再把非锚定窗口的数据整体丢弃或和正常时段混算，而是分开统计：

**连续波动率（有实时锚点的正常时段）**
```
σ_intraday = 用全天链上 OHLCV 算的标准波动率——这段时间有真实参考价纠偏，按第 1.3 节的 σ_price 方法照常算
```

**跳空风险（锚定真空窗口，单独统计，不并入 σ_intraday）**
```
GapJump = 历史"锚定真空窗口开始前最后价格 → 窗口结束后第一笔价格"的跳变幅度分布（如周五收盘价 → 周日期货重开后首笔链上价）
```

- 这是 Merton 跳跃扩散模型的思路：正常时段用连续随机游走描述（沿用第 1.3 节的 GBM 框架），在已知、可预测的锚定真空窗口上叠加一个离散跳跃项，两者不应该用同一个 σ 描述。
- `GapJump` 样本量天然很小（一年约 50 个周末），置信度低，需要和 σ_price 一样有 `unavailable`/样本不足的降级处理，不能拿小样本冒充稳定分布。
- 用途：推荐区间宽度（第 1.4 节）对这类池子需要额外校验——区间下限至少要能扛住历史 `GapJump` 的最大/近似分位数幅度，而不是只按 `σ_intraday` 用 GBM 公式推算，否则遇到真实跳空，推荐区间会系统性偏窄。

### 4.4 发行方 / 储备透明度（定性准入门槛，不是打分项）

链上指标算不出"发行方是否足额持有底层资产、有没有清算/合规风险"，只能做定性准入门槛：要求有可验证的储备证明/审计披露才能进入候选池，达不到直接不参与打分——跟第 0 节的 token 白名单门槛是同一类处理，不进复合分公式。

### 4.5 IL 风险分类表新增一档

第 1.3 节的四档币对分类（稳定币/主流/主流长尾/长尾）都基于加密资产间的相关性假设，RWA 代币需要单独一档：与主流加密资产相关性通常较低（大盘股指数和 BTC/ETH 不是强相关），自身长期波动率可能低于长尾币，但叠加了 4.3 节的跳空风险，系数不能直接套用现成档位，需要单独标定。

### 4.6 桥 / 包装层风险（如适用）

若代币是从其他链桥接而来的包装资产，额外叠加一层桥安全风险，与原生 BSC 资产不是一个风险量级，需要单独标注，不能和链上原生代币混在同一风险评级里。

## 5. 已知局限 / v2 路线

- **GBM / 无漂移假设**：σ_price 驱动的 IL 估算、跳仓频率、推荐区间三个模型都假设价格服从无漂移几何布朗运动。真实价格有趋势（尤其新币/低流动性币对），单边行情下实际出界速度会比模型快，模型偏乐观，需要在展示文案里注明"基于历史波动率的近似估算，不是保证"。
- **`w_typical`（跳仓频率用的"典型区间"）是 TickLens 快照，本身有噪音**：某一时刻的集中度分布可能被单个大 LP 的头寸主导，不代表长期典型值，v2 可考虑对 TickLens 快照做多次采样平均。
- **OHLCV 粒度**：v1 用 GeckoTerminal 日线算 σ_price，对波动极快的长尾币对可能低估短期波动；v2 可视需要切换到小时线，但要评估该池子是否有足够历史深度和 API 额度。
- 大户集中度缺数据源，v1 完全不参与打分。
- CAKE APR 是"当前 emission 快照外推"，emission 调整频率未纳入模型，存在高估长期收益的风险，展示时需要免责说明。
- 复合分权重（0.30/0.25/0.25/0.10/0.10）是首版经验值，需要用真实候选池数据跑一遍分布后再校准，不应视为最终定论。
- **RWA 参考价数据源尚未选定**：第 4.2 节的 TrackingError 依赖链下 NAV/期货公允价数据源，当前只是标出需求，具体接哪个供应商（预言机 feed / 发行方披露）没有调研落地，属于本文档尚未闭环的一项。
